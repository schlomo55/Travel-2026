# Lantern — the design language of *Living the dream*

*Warm gold light against true black. Precious physical materials — leather luggage tags, torn
paper — lit by neon. Not cold sci-fi: a lit instrument panel at night that still smells of paper
and leather.*

Approved 2026-07-26 (`lantern-public-product.md` §LANTERN). This file is the implementer's
reference; the visual target is [`lantern-preview.html`](./lantern-preview.html) in this folder
(open it in a browser — it has all six screens and a motion toggle).

Everything here lives in **`app/src/app.css`**. Nothing in this document is aspirational: the
contrast table at the bottom is generated by `npm run check:contrast`, which reads the real hex
values out of `app.css` and fails the build if a pair drops below its threshold.

---

## 1. Two themes, dark by default

**Amended 2026-08-12 (§14).** The dark-only decision of 2026-07-26 is rescinded. There are two
themes now, and dark is still the one you get:

- `:root` is dark. It is the default, and the default is the **absence** of an attribute — no
  `data-theme="dark"` exists anywhere. A cold boot therefore paints dark with nothing to read,
  nothing to wait for and nothing to flash.
- `:root[data-theme='light']` is light, chosen in Settings, stored in the settings record and
  mirrored into `localStorage` so four lines in `index.html` can apply it before the first paint.

There is no `light-dark()`, no `prefers-color-scheme` and no "follow the system" anywhere in the
build. **The theme is an app setting, not an operating-system one**: this phone is in dark mode
all day and the app is still read on a bright train.

The other look setting is **Calm motion** (§5).

**The driver overlay keeps its raw look and loses its magic numbers.** §RULES 4
says a stranger reads that card in daylight, so it takes no Lantern colour: the two
ends are `--driver-bg` `#000000` and `--driver-ink` `#ffffff`, and every value
between them is white at 95 / 60 / 20 / 8 % over the black. They are written as
plain hex rather than `color-mix()` for one reason — `check-contrast.mjs` parses hex
out of `app.css`, and a value the gate cannot read is a value the gate cannot
defend. `--driver-accent` (`#e6c88a`) is the single non-neutral: the phrase held up
to be *asked*, kept distinguishable from the address being *shown*. All six carry
gate rows.

**The expense-category swatches are not here.** They live in
`src/lib/logic/swatches.ts`, because an `ExpenseCategory.color` is written to the
database and to every backup file — a `var(--…)` would not survive the export. Six
named constants, deliberately not gold (a spending chart needs six colours a
traveller can tell apart), and never a text colour or a text ground.

### Per-trip / per-stop identity

`accentHue` stays in the data model but no longer re-tints the app. It survives in exactly three
tokens, composed on every element so `style="--h:210"` re-tints a subtree:

```css
--stop:      hsl(var(--h, var(--accent-h)) 55% 66%);   /* stay bars, station dots, route lines */
--stop-soft: hsl(var(--h, var(--accent-h)) 40% 13%);   /* the fill behind identity text */
--stop-text: hsl(var(--h, var(--accent-h)) 60% 80%);   /* identity text */
```

The lightness values are chosen so the **worst hue on the wheel** (240°, blue) still passes:
`--stop-text` 8.98:1 on a card, `--stop` 5.00:1. See the table.

### Glow-elevation — importance is light, not shadow

Drop shadows are invisible on true black, so elevation is a **glow**. Three steps, defined once:

| Token | Meaning | Where |
|---|---|---|
| `--glow-1` | a resting surface | every `.card`, the tab pill |
| `--glow-2` | the thing you came for | `.card.lit`, `.btn.primary`, toast |
| `--glow-3` | the moment | `.card.hero` — today's hero, the countdown |

Plus `--glow-neon` (progress fills), `--glow-glyph` / `--glow-glyph-neon` (`filter: drop-shadow`
for SVG strokes). `--shadow-card` is kept as an alias of `--glow-1` so old rules keep working.
Utility classes `.elev-1 / .elev-2 / .elev-3` apply them to non-card surfaces.

**Never invent a fourth step.** If something needs to be louder than `--glow-3`, it needs a
different position on the screen, not more light.

### Geometry

4/8 grid: `--s1 4px`, `--s2 8px`, `--s3 12px`, `--s4 16px`, `--s5 24px`, `--s6 32px`.
Radius: `--radius 22px` (cards), `--radius-lg 24px` (photo cards), `--radius-sm 12px` (small),
`--radius-pill 999px` (pills, nav). `--nav-h 74px`.

### The type ladder (2026-08-12)

Six steps, and nothing between them.

| Token | Value | Use |
|---|---|---|
| `--text-xs` | `11px` | a caps micro-label, and **only** a label — never the number beside one |
| `--text-sm` | `13px` | the floor for anything read as a value: prices, times, station names |
| `--text-base` | `16px` | body |
| `--text-lg` | `20px` | section heads, a card's own number, a control's glyph |
| `--text-title` | `28px` | screen titles, the big number on a card |
| `--text-hero` | `40px` | the one number on the screen |

Before this run the app rendered **45 distinct sizes**, 192 of them crowded between
8.5 px and 15.5 px, with only 20 of 317 declarations going through a token at all.
That is not a hierarchy; it is noise that happens to be legible in daylight. Sizes
were snapped to the **nearer** rung, up for values and down for decoration at an
exact midpoint. `--text-md` (13.5 px) and the old `--text-lg` (18 px) are gone.

**Floors.** No text under 11 px. No *value* under 13 px — the sub-10 px offenders
the audit found (`CABIN`/`SEAT`/`CHECKED`, the rail-end `FROM`/`TO` labels, the
cost-ledger status chip at 9.5 px, the connector state pill at 9.9 px) are all on
11 px now, and the two chips additionally grew **an outline in their own colour**,
because a status told only in tint is a status not told at all on a dimmed screen.

Off the ladder, named, and deliberately so — these are not running text:

| Token | Value | Why it is exempt |
|---|---|---|
| `--glyph-scene` | `46px` | the emoji standing in for a missing cover photo |
| `--glyph-scene-lg` | `74px` | the same, at guide-hero scale |
| `--text-fluid-city` | `clamp(26px, 8.4vw, 36px)` | a stop name must not push a 360 px phone sideways |
| `--text-fluid-code` | `clamp(19px, 6.4vw, 26px)` | a confirmation code read out at a counter |
| `--text-fluid-card` | `clamp(20px, 6.6vw, 29px)` | the number on a travel card, read at a gate |
| `--driver-zh` / `--driver-addr` / `--driver-ask` | clamps to 62 / 27 / 31 px | §RULES 4: read at arm's length across a taxi seat, by someone else |

The ladder is enforced by the rehearsal, not by review: **"Type ladder · six rungs,
nothing between"** sweeps four real screens and fails on any rendered size that is
not a rung or one of the exemptions above. It reads the DOM rather than the CSS, so
a size that creeps back through an inline style is caught too.

### The two new bundled faces

Chosen with the ui-ux-pro-max google-fonts search (queries: *"typewriter monospace slab font for
editorial travel guide"*, *"handwritten script font for city titles"*, then the plan's named
candidates), from the plan's own shortlist:

- **Special Elite** — Display, latin + latin-ext, one weight, popularity rank 327, Astigmatic.
  It is the typewriter in the Kyoto mockup: struck-ink irregularity without being a novelty face.
  The generic slab serifs the search surfaced first (Hepta Slab, Josefin Slab, Arvo…) are *slabs*,
  not *typewriters* — they have no strike, so the torn-paper card would read as a design choice
  rather than as a document. Rejected.
- **Caveat Variable** — Handwriting, variable `wght 400–700`, popularity rank 123, Impallari Type.
  Chosen over Dancing Script (too formal/looped for a hand-written place name) and over the
  Playwrite family (school-primer handwriting, and no latin subset declared in the catalogue).

Both are installed from Fontsource (`@fontsource/special-elite`,
`@fontsource-variable/caveat`) and declared by hand in **`app/src/lantern-fonts.css`** rather than
imported, because:

- Caveat ships one stylesheet covering latin + latin-ext + cyrillic + cyrillic-ext — ~117 KB of
  Cyrillic this English-only app never renders;
- Fontsource lists a `.woff` fallback beside every `.woff2`, and every browser this app targets
  reads woff2 — the `.woff` would be dead weight in the repo and in the precache.

No font binary is copied into the repo; the packaged files are still the source, Vite hashes them
and Workbox precaches them (the `woff2` glob), so both faces work in airplane mode.

**Budget: 128.2 KB added** (Special Elite latin 53.3 KB + Caveat latin 74.9 KB) against the
≤400 KB allowance. Verify with `ls app/dist/assets/{special-elite,caveat}*`.

## 5. Motion

Cinematic within §MOTION limits: **150–400 ms**, transform/opacity only, interruptible, never
blocking input, nothing animates during scroll.

| Token | Value |
|---|---|
| `--motion-fast` | 150 ms |
| `--motion` | 240 ms |
| `--motion-slow` | 380 ms |
| `--ease-out` | `cubic-bezier(.16, 1, .3, 1)` |
| `--ease-in-out` | `cubic-bezier(.4, 0, .2, 1)` |
| `--stagger-step` | 40 ms |

| Utility | What it does |
|---|---|
| `.u-rise` | one element enters (opacity + 14 px lift). `style="--i:3"` places it in a stagger |
| `.u-fade` | crossfade — tab and view changes |
| `.u-stagger` | its children enter one after another at 40 ms/item; **everything past the eighth child lands together**, because a stagger that keeps counting turns a long list into a slow list |
| `.u-pulse` | the ONLY infinite loop in the app: "you are here" |

Set-pieces built in Phase 1:

| Set-piece | Where | How it stays cheap |
|---|---|---|
| staggered card entrance | shelf cards, timeline items, runbook steps | `.u-rise` / `.u-stagger`, capped at the 8th child |
| progress ring fill (~1 s) | `ProgressRing.svelte` | a **module-scoped** `filledOnce` set, keyed by the ring's `id`: each Lists segment fills once per page load and is instant on every re-entry |
| route map draws itself (~600 ms) | `RouteMap.svelte` | `pathLength="1"` + `stroke-dashoffset` so one keyframe fits every leg length; a module-scoped `drawnOnce` flag stops it replaying |
| pulsing "you are here" | the route map's gold ring | `.u-pulse`, still the only infinite loop. An SVG circle needs `transform-box: fill-box` or the scale flings it off-canvas |

### Reduced motion — two independent switches

1. The phone's `prefers-reduced-motion: reduce`.
2. **Settings → Motion → Calm motion**, stored as `Settings.calmMotion`, applied by `App.svelte`
   as `html.calm`.

Both collapse `animation-duration`, `animation-delay`, `transition-duration`, `transition-delay`
and force `animation-iteration-count: 1` (so an infinite loop does not spin at 0.01 ms). Because
every entrance uses `animation-fill-mode: both`, collapsing the duration leaves elements at their
**final** state — nothing is left invisible. That is the trap to remember when adding a new
animation: entrances must animate *to* the resting state, never *from* it.

## 6. Do / don't

**Do**

- Use gold for the brand voice, neon only for progress and completion.
- Say importance with a glow step, position and type size — in that order.
- Keep every text colour on the contrast table. Add the pair to `scripts/check-contrast.mjs`
  when you introduce a new surface.
- Keep tap targets ≥44 px; the app is used one-handed at 22:00 on 8 % battery.
- Put text on a photo only inside the scrimmed area, in `--on-photo`.

**Don't**

- Don't put text in `--deco`, `--gold-dim` or `--line` — they are below the body threshold on
  purpose. They are hairlines, watermarks and dead glyphs.
- Don't add a fourth glow step or a second infinite animation.
- Don't write a colour, a glow or a shadow that exists only in one theme's block. Every
  token is declared in `:root`; the light block only ever RESTATES one (§14).
- Don't re-tint the app with the trip hue — it belongs to the shelf badge, the stay bars and the
  route-map lines, nothing else.
- Don't style the driver overlay. §RULES 4: it stays a plain black/white daylight-readable card.
  Lantern styles its frame, never its content.
- Don't animate anything during scroll, and never let motion gate an input.

## 8. Contrast validation

Generated by `node app/scripts/check-contrast.mjs --table`, which parses the token values out of
`app/src/app.css`. It runs as part of `npm run build` (`npm run check:contrast`) and exits 1 on
any failure — the table cannot silently rot.

Thresholds: **4.5:1** for body text, **3:1** for large text (≥24 px, or ≥18.66 px bold) and for the
boundaries of interactive components. Rows marked *decorative* are reported for the record and are
forbidden from carrying text.

Composited backgrounds are computed, not approximated: `--paper-lit` is the wash at its peak over
the canvas, `--*-bg@card` / `--*-bg@paper` are the status fills over their surface at the alpha
the CSS actually declares, and `--scrim-worst` is the photo scrim's 80 % **black** over a
pure-white photo — black in both themes, because a photo is its own ground. Hue-parameterised
rows report the **worst hue on the wheel**, sampled every 5°.

each, resolving the light block against the dark one exactly as the cascade does. A failure in

### Known sub-3:1 boundaries, on the record

`--line` (1.37:1) and `--leather-edge` (2.23:1) are below the 3:1 non-text threshold **on
purpose**. On a true-black canvas, card separation is carried by the surface lift plus
`--glow-1`'s gold hairline, not by a border — a 3:1 outline around every card would turn the
screen into a wireframe and destroy the material illusion. Nothing functional depends on seeing
them: every *interactive* boundary uses `--line-2`, which passes on all three surfaces.

Gap D added four more of the same species, and one rule with them: **a material's own edge is
decorative; the boundary of a control is `--line-2`.**

| Token | On | Ratio | Why it may stay |
|---|---|---|---|
| `--tag-edge` | `--tag-leather-2` | 2.00:1 | the punched ring and the dashed rules inside a luggage tag. The tag's *buttons* moved to `--line-2` (3.30:1 over their own darkened ground) in this run — they were on `#6e5c44` at 2.66:1 and that was a real failure, not a decision |
| `--navy-edge` | `--paper` | 1.56:1 | the material edge of the Total-Spent hero. Its affordance is a full-width card carrying the largest number on the screen |
| `--paper-rule` | `--paper-well` | 2.00:1 | the rule *between* accordion rows. The accordion's own outer boundary took `--line-2` (3.78:1) in this run |
| `--driver-line` | `--driver-bg` | 1.66:1 | §RULES 4 outranks Lantern on that card: it may not be tinted, and the address field's affordance is its lifted ground and its ⧉ glyph |

The six mocked screens set the vocabulary; Phase 2 spent it everywhere else. Four devices were
added to the system, all of them in `app.css` so no screen invents its own:

| Device | What it is | Where |
|---|---|---|

**Tap targets.** Everything interactive is ≥44 px. Two controls keep a smaller *drawing* and carry
the target invisibly — `.cbox` (34 px box, `::after { inset:-5px }`) and `.editbtn` (34 px, same
trick) — because growing them for real would have turned every list into a ladder. The rule that
comes with it: any container holding two of them needs ≥10 px of gap, or the invisible rings
overlap (see `Documents.svelte` `.dacts`).

**Empty states.** Copy lives in `strings.ts` under `S.empty`, one entry per surface, each written
to (1) name what is missing in the traveller's words, (2) say what would fill it, concretely, and
(3) offer the action that fills it — but only where the screen honestly has one. `S.empty.templates`
and `S.empty.notes` carry no action because nothing on that screen can create one.

Info is the one screen with a *screen-level* empty state as well as section-level ones: a trip with
nothing filed at all gets one honest card instead of five empty sections, while a trip with
*something* draws its spine (route · vault · statistics) with each section's own empty state.

**Frames, not content.** The driver overlay took a Lantern frame — a gold inset hairline and the
app's chrome on its close button — and nothing else. Every character a stranger reads is still
plain white on plain black (§RULES 4). The document viewer's frame followed the same rule.

**Icon, splash, wordmark.** Same sun-behind-mountains motif, redrawn on true black: a gold sun
disc behind two ridges, each ridge carrying a rim-light stroke (on black a silhouette needs an edge
to exist), a lit horizon bar, and a radial gold glow. `icon-src/*.svg` → `npm run icons` →
`public/icons/*.png`; `npm run android:assets` fans the same source out to the launcher. The web
manifest, the Android adaptive-icon plate and `ic_launcher_background` are all `#000000` now.

### The owner decision: the guide's long read leaves the paper

**Approved 2026-08-12. This supersedes strict pixel-fidelity to the Kyoto mockup for
body prose, and only for body prose.**

The city guide is the longest surface in the app — Zhangjiajie runs to about 11,800
px — and every word of it was set in Special Elite, a distressed typewriter face, at
13.5 px, much of it on a near-white cream sheet. That is a document at a desk in
daylight. It is not a thing a dark-adapted eye reads in a hotel room at 22:00, which
is when this page is actually opened.

What stays: the torn cream stock, the typewriter **headings**, the Caveat city title,
the day-by-day accordion, the cream-framed thumbs, the glowing map pills. The mockup's
voice is intact.

moved off the cream**. "Getting there & money" is six lines and keeps the paper — it
reads like the document it is. "About this place" runs to thousands of pixels and now
sits on `--card` with `--ink` on it, keeping its typewriter heading and the cream
underline `.ghead` already uses. Short blocks keep the material; the long read gets
the ground the rest of the app is read on.

One bug fell out of doing it: `.paper :global(p)` had never matched the story at all.
md-lite renders a stop's detail as inline HTML inside **one bare `<div>`** with no
paragraph tags, so the rule aimed at `p`/`li` reached the short block's list items
and never the longest prose on the page. The face is set on the panel now.

Guarded by **"City guide · the long read is legible at night"**, which asserts both
halves — the long read is not typewriter and not on cream, *and* the short block still
is. Either one alone is the bug back.

### Designed for daylight, not inverted

An inverted dark theme is a dark theme with the lights broken. Everything that made Lantern work
at 22:00 — a glow that says "this is the thing you came for", a gold that reads as warm light, a
leather tag lit from above — does the opposite on paper. So the light palette was drawn from the
same materials in a different light, and only then measured:

| | Dark | Light | Why not simply invert |
|---|---|---|---|
| ground | `#000000` true black | `#f2e8d5` cream paper | the inverse of black is #fff, and a white app is a form, not a travel journal |
| lift | a surface rises by getting **lighter** | a card rises toward **white**, chrome settles into a **deeper** stock | on paper, "lifted" and "recessed" swap directions |
| the luggage tag | leather, `#372d24` | **manila**, `#e9d8b8` | a real tag in daylight is card stock; leather at night is the same object under a lamp |
| the money hero | navy `#131b22` | pale slate `#dde8f0` | it stays the one cool surface without becoming a hole in the page |
| the accordion well | `#0d0c0a`, a dark well | `#ece1c8`, a lit recess | a well is a recess, not a colour |
| importance | glow strength | **shadow depth** | see below |
| the identity hues | `hsl(h 55% 66%)` fill, `hsl(h 60% 80%)` text | `hsl(h 55% 35%)` fill, `hsl(h 55% 27%)` text | an 80 %-light text is 3.89:1 on cream at the worst hue — not a near miss |

### The two rules that fell out of it

**1. Gold-as-text is recalibrated, and the dark gold may never carry text on cream.**
`--gold: #e8b04b` is **1.60:1** on the light `--paper` — invisible, not merely weak. The light
palette's gold is `#7d5612`, and `--gold-light` — "gold at TEXT weight" — is *darker* still at
`#6f4b0e`. The token name describes a role, not a luminance: on black, text weight means
brighter; on paper it means darker. The same is true of the status hues, all darkened, and of
`--neon`, which goes from cyan `#3ec6f5` to deep sky `#0a6288`.

The status **washes** could not simply follow their hues down. A 14 % veil of a dark status
colour *darkens* a light ground and eats the very contrast it exists to frame — `.chip.crit` came
out at 3.93:1. On paper each wash is a pale tint of the hue at a higher alpha instead, so it
lifts the ground: `--crit-bg: rgba(255, 170, 163, 0.45)`. The gate reads the declared rgba rather
than reconstructing it from the status token, precisely because the two no longer match.

**2. Glow-elevation becomes soft warm shadow.** A gold halo needs a dark ground to read as light;
on cream the identical shadow is a smudge, and the card looks damp rather than important. All
three steps, and every named light with them, are restated as a warm brown-black shadow.
`--glow-1/2/3` keep their meaning (resting card · the thing you came for · the moment) and change
their mechanism. `--glow-text` becomes `none`: a numeral does not glow in daylight.

Doing that honestly required tokenising the lighting first. Thirteen hand-written
`rgba(232, 176, 75, …)` box-shadows were still scattered across twelve components — exactly the
species of magic number Gap D folded away, surviving only because they are shadows and not
colours. They are now `--glow-focus`, `--glow-lantern(-strong)`, `--glow-switch`,
`--glow-halo(-strong, -soft)`, `--glow-plan(-now)`, `--glow-photo-card`, `--glow-sheet`,
`--glow-tag`, `--glow-fab`, `--glow-text`, `--glow-line-air`, `--shadow-paper` and
`--shadow-thumb`. Raw glows in `app/src/**/*.svelte`: **13 → 1**, and the survivor is the driver
overlay's frame, which is deliberately identical in both themes.

`check-contrast.mjs` grew a matching guard: its undefined-token sweep now covers `--glow-*`,
`--shadow-*` and `--on-*` as well as `--text-*`/`--glyph-*`/`--driver-*`. An undefined shadow
token fails even more quietly than an undefined size — it does not inherit a shadow, it draws
*nothing*, and a card with no elevation looks like a card somebody designed flat.

### `--on-material`: the ink, not the paper

`--cream` was doing two jobs. It is a paper **stock** (the torn guide sheet, the mount round a
photo thumb, the caption colour on a photo scrim) *and* it was the ink on every dark material:
the tag's `KIND` header and its button labels, the accordion's day titles, the guide's typewriter
headings. That works only while every material is dark. In light the tag is manila and the well
is a lit recess, so the ink has to flip while the stock must not — and one token cannot do both.
Twelve declarations across ten selectors moved to a new `--on-material`; `--cream` kept the
four uses where it really is
paper. The gate followed: the five `--cream`-as-ink pairs are `--on-material` pairs now, in both
palettes.

### Four things are their own ground, and are IDENTICAL in both themes

Photos and their scrims · the golden-hour scene (`--dusk-*`, `--scene-floor`, `--on-scene`) ·
the battery day meter's cell · **the driver overlay** (§RULES 4, which outranks Lantern: a
stranger reads that card in daylight either way).

The contrast script was corrected to match. `--scrim-worst` had been composited from `--paper`,
which was only ever right because `--paper` happened to be `#000000`; it now composites literal
black. Every dark number is unchanged. The reasoning no longer is.

### Do / don't, for this theme

**Do** run every new pair through `npm run check:contrast` — it checks **both** palettes and
fails the build on either. **Do** restate a token in the light block only when it must change:
everything unstated is inherited from `:root`, and the aliases (`--accent`, `--accent-deep`,
`--btn-fill`) re-point for free because a custom property resolves against the winning definition
of what it names.

**Don't** use `--gold`, or any other dark-theme value, as text on the light ground without
measuring it first. **Don't** add a light-only or dark-only *rule*: the light block holds values,
not layout, and the only structural exceptions in the whole run are `color-scheme` and the native
date picker's, one line each. **Don't** reach for `prefers-color-scheme` — the owner chose the
theme, not the phone.

### How it is applied, and why there is no flash

The theme lives in the settings record like everything else. Dexie is asynchronous, so a
light-theme user would watch black flash to cream on every launch if that were the only source.
`lib/logic/theme.ts` therefore mirrors the choice into `localStorage`, and four lines in
`index.html` read it inside `<head>`, before `<body>` exists. Dexie stays the source of truth;
the mirror only has to be right at boot. `App.svelte` deliberately does **nothing** until the
live query answers — treating "not loaded yet" as dark would repaint the screen black for one
frame, which is the exact flash the boot script exists to prevent.

The rehearsal asserts this rather than assuming it: it records `data-theme` at
`DOMContentLoaded`, which the app's own theme effect cannot have reached by then, so anything
found there was written by the boot script.
