# Lantern — the design language of *Living the dream*

*Warm gold light against true black. Precious physical materials — leather luggage tags, torn
paper — lit by neon. Not cold sci-fi: a lit instrument panel at night that still smells of paper
and leather.*

Approved 2026-07-26 (`lantern-public-product.md` §LANTERN). This file is the implementer's
reference; the visual target is [`lantern-preview.html`](./lantern-preview.html) in this folder
(open it in a browser — it has all six screens and a motion toggle).

Everything here lives in **`app/src/app.css`**. Nothing in this document is aspirational: the
contrast table at the bottom is generated by `npm run check:contrast`, which reads the real hex
values out of `app.css` and fails the build if a pair drops below its threshold.

---

## 1. Dark only

The light theme was removed. Tokens are single-value: there is no `light-dark()`, no
`[data-theme]` attribute, no theme switch in Settings, and no `Settings.theme` field. `index.html`
declares one `theme-color` (`#000000`) and `color-scheme: dark`.

The only look setting that survives is **Calm motion** (§5).

### Per-trip / per-stop identity

`accentHue` stays in the data model but no longer re-tints the app. It survives in exactly three
tokens, composed on every element so `style="--h:210"` re-tints a subtree:

```css
--stop:      hsl(var(--h, var(--accent-h)) 55% 66%);   /* stay bars, station dots, route lines */
--stop-soft: hsl(var(--h, var(--accent-h)) 40% 13%);   /* the fill behind identity text */
--stop-text: hsl(var(--h, var(--accent-h)) 60% 80%);   /* identity text */
```

The lightness values are chosen so the **worst hue on the wheel** (240°, blue) still passes:
`--stop-text` 8.98:1 on a card, `--stop` 5.00:1. See the table.

### Glow-elevation — importance is light, not shadow

Drop shadows are invisible on true black, so elevation is a **glow**. Three steps, defined once:

| Token | Meaning | Where |
|---|---|---|
| `--glow-1` | a resting surface | every `.card`, the tab pill |
| `--glow-2` | the thing you came for | `.card.lit`, `.btn.primary`, toast |
| `--glow-3` | the moment | `.card.hero` — today's hero, the countdown |

Plus `--glow-neon` (progress fills), `--glow-glyph` / `--glow-glyph-neon` (`filter: drop-shadow`
for SVG strokes). `--shadow-card` is kept as an alias of `--glow-1` so old rules keep working.
Utility classes `.elev-1 / .elev-2 / .elev-3` apply them to non-card surfaces.

**Never invent a fourth step.** If something needs to be louder than `--glow-3`, it needs a
different position on the screen, not more light.

### Geometry

4/8 grid: `--s1 4px`, `--s2 8px`, `--s3 12px`, `--s4 16px`, `--s5 24px`, `--s6 32px`.
Radius: `--radius 22px` (cards), `--radius-lg 24px` (photo cards), `--radius-sm 12px` (small),
`--radius-pill 999px` (pills, nav). `--nav-h 74px`.

### The two new bundled faces

Chosen with the ui-ux-pro-max google-fonts search (queries: *"typewriter monospace slab font for
editorial travel guide"*, *"handwritten script font for city titles"*, then the plan's named
candidates), from the plan's own shortlist:

- **Special Elite** — Display, latin + latin-ext, one weight, popularity rank 327, Astigmatic.
  It is the typewriter in the Kyoto mockup: struck-ink irregularity without being a novelty face.
  The generic slab serifs the search surfaced first (Hepta Slab, Josefin Slab, Arvo…) are *slabs*,
  not *typewriters* — they have no strike, so the torn-paper card would read as a design choice
  rather than as a document. Rejected.
- **Caveat Variable** — Handwriting, variable `wght 400–700`, popularity rank 123, Impallari Type.
  Chosen over Dancing Script (too formal/looped for a hand-written place name) and over the
  Playwrite family (school-primer handwriting, and no latin subset declared in the catalogue).

Both are installed from Fontsource (`@fontsource/special-elite`,
`@fontsource-variable/caveat`) and declared by hand in **`app/src/lantern-fonts.css`** rather than
imported, because:

- Caveat ships one stylesheet covering latin + latin-ext + cyrillic + cyrillic-ext — ~117 KB of
  Cyrillic this English-only app never renders;
- Fontsource lists a `.woff` fallback beside every `.woff2`, and every browser this app targets
  reads woff2 — the `.woff` would be dead weight in the repo and in the precache.

No font binary is copied into the repo; the packaged files are still the source, Vite hashes them
and Workbox precaches them (the `woff2` glob), so both faces work in airplane mode.

**Budget: 128.2 KB added** (Special Elite latin 53.3 KB + Caveat latin 74.9 KB) against the
≤400 KB allowance. Verify with `ls app/dist/assets/{special-elite,caveat}*`.

## 5. Motion

Cinematic within §MOTION limits: **150–400 ms**, transform/opacity only, interruptible, never
blocking input, nothing animates during scroll.

| Token | Value |
|---|---|
| `--motion-fast` | 150 ms |
| `--motion` | 240 ms |
| `--motion-slow` | 380 ms |
| `--ease-out` | `cubic-bezier(.16, 1, .3, 1)` |
| `--ease-in-out` | `cubic-bezier(.4, 0, .2, 1)` |
| `--stagger-step` | 40 ms |

| Utility | What it does |
|---|---|
| `.u-rise` | one element enters (opacity + 14 px lift). `style="--i:3"` places it in a stagger |
| `.u-fade` | crossfade — tab and view changes |
| `.u-stagger` | its children enter one after another at 40 ms/item; **everything past the eighth child lands together**, because a stagger that keeps counting turns a long list into a slow list |
| `.u-pulse` | the ONLY infinite loop in the app: "you are here" |

Set-pieces built in Phase 1:

| Set-piece | Where | How it stays cheap |
|---|---|---|
| staggered card entrance | shelf cards, timeline items, runbook steps | `.u-rise` / `.u-stagger`, capped at the 8th child |
| progress ring fill (~1 s) | `ProgressRing.svelte` | a **module-scoped** `filledOnce` set, keyed by the ring's `id`: each Lists segment fills once per page load and is instant on every re-entry |
| route map draws itself (~600 ms) | `RouteMap.svelte` | `pathLength="1"` + `stroke-dashoffset` so one keyframe fits every leg length; a module-scoped `drawnOnce` flag stops it replaying |
| pulsing "you are here" | the route map's gold ring | `.u-pulse`, still the only infinite loop. An SVG circle needs `transform-box: fill-box` or the scale flings it off-canvas |

### Reduced motion — two independent switches

1. The phone's `prefers-reduced-motion: reduce`.
2. **Settings → Motion → Calm motion**, stored as `Settings.calmMotion`, applied by `App.svelte`
   as `html.calm`.

Both collapse `animation-duration`, `animation-delay`, `transition-duration`, `transition-delay`
and force `animation-iteration-count: 1` (so an infinite loop does not spin at 0.01 ms). Because
every entrance uses `animation-fill-mode: both`, collapsing the duration leaves elements at their
**final** state — nothing is left invisible. That is the trap to remember when adding a new
animation: entrances must animate *to* the resting state, never *from* it.

## 6. Do / don't

**Do**

- Use gold for the brand voice, neon only for progress and completion.
- Say importance with a glow step, position and type size — in that order.
- Keep every text colour on the contrast table. Add the pair to `scripts/check-contrast.mjs`
  when you introduce a new surface.
- Keep tap targets ≥44 px; the app is used one-handed at 22:00 on 8 % battery.
- Put text on a photo only inside the scrimmed area, in `--on-photo`.

**Don't**

- Don't put text in `--deco`, `--gold-dim` or `--line` — they are below the body threshold on
  purpose. They are hairlines, watermarks and dead glyphs.
- Don't add a light theme back, a fourth glow step, or a second infinite animation.
- Don't re-tint the app with the trip hue — it belongs to the shelf badge, the stay bars and the
  route-map lines, nothing else.
- Don't style the driver overlay. §RULES 4: it stays a plain black/white daylight-readable card.
  Lantern styles its frame, never its content.
- Don't animate anything during scroll, and never let motion gate an input.

## 8. Contrast validation

Generated by `node app/scripts/check-contrast.mjs --table`, which parses the token values out of
`app/src/app.css`. It runs as part of `npm run build` (`npm run check:contrast`) and exits 1 on
any failure — the table cannot silently rot.

Thresholds: **4.5:1** for body text, **3:1** for large text (≥24 px, or ≥18.66 px bold) and for the
boundaries of interactive components. Rows marked *decorative* are reported for the record and are
forbidden from carrying text.

`--scrim-worst` is the photo scrim's 80 % black over a pure-white photo. Hue-parameterised rows

### Known sub-3:1 boundaries, on the record

`--line` (1.37:1) and `--leather-edge` (2.23:1) are below the 3:1 non-text threshold **on
purpose**. On a true-black canvas, card separation is carried by the surface lift plus
`--glow-1`'s gold hairline, not by a border — a 3:1 outline around every card would turn the
screen into a wireframe and destroy the material illusion. Nothing functional depends on seeing
them: every *interactive* boundary uses `--line-2`, which passes on all three surfaces.

## 8a. Phase 1 — the six screens, as built

| Screen | Lantern devices |

Two honesty rules were load-bearing in this phase and are worth keeping in mind:

- **The timeline never invents a clock.** `logic/timeline.ts` lifts a time out of a
  plan item only when the item *begins* with one; everything else falls into the
  "Anytime" block. It also puts a removed `**` back so md-lite emphasis stays
  balanced, and only splits title from detail where the markers before the split
  are balanced.
- **A tile whose data is absent is not drawn.** No continent count (nothing in the
  data says which continent a stop is on), no distance under two coordinates, no
  star rating a spot did not carry.

## 8b. Phase 2 — everything un-mocked, in the same language

The six mocked screens set the vocabulary; Phase 2 spent it everywhere else. Four devices were
added to the system, all of them in `app.css` so no screen invents its own:

| Device | What it is | Where |
|---|---|---|
| `.switch` | a 46 × 28 gold track drawn from a real checkbox inside a 44 px row — the shape every on/off setting takes | Settings, every `toggle` field in `SchemaForm` |
| gold focus | `input:focus` = gold border + a 3 px gold halo + a 14 px glow, *plus* the existing `:focus-visible` outline for keyboard | every field in the app |
| `.seclabel` | a caps section header with a quiet sub-line, for stretches that are not cards | Lists, Info, Backup |
| `EmptyState.svelte` | the one shape an absence takes: dashed border, gold-ringed glyph, Fraunces line, one sentence, and the button that fills it | 21 surfaces |

**Tap targets.** Everything interactive is ≥44 px. Two controls keep a smaller *drawing* and carry
the target invisibly — `.cbox` (34 px box, `::after { inset:-5px }`) and `.editbtn` (34 px, same
trick) — because growing them for real would have turned every list into a ladder. The rule that
comes with it: any container holding two of them needs ≥10 px of gap, or the invisible rings
overlap (see `Documents.svelte` `.dacts`).

**Empty states.** Copy lives in `strings.ts` under `S.empty`, one entry per surface, each written
to (1) name what is missing in the traveller's words, (2) say what would fill it, concretely, and
(3) offer the action that fills it — but only where the screen honestly has one. `S.empty.templates`
and `S.empty.notes` carry no action because nothing on that screen can create one.

Info is the one screen with a *screen-level* empty state as well as section-level ones: a trip with
nothing filed at all gets one honest card instead of five empty sections, while a trip with
*something* draws its spine (route · vault · statistics) with each section's own empty state.

**Frames, not content.** The driver overlay took a Lantern frame — a gold inset hairline and the
app's chrome on its close button — and nothing else. Every character a stranger reads is still
plain white on plain black (§RULES 4). The document viewer's frame followed the same rule.

**Icon, splash, wordmark.** Same sun-behind-mountains motif, redrawn on true black: a gold sun
disc behind two ridges, each ridge carrying a rim-light stroke (on black a silhouette needs an edge
to exist), a lit horizon bar, and a radial gold glow. `icon-src/*.svg` → `npm run icons` →
`public/icons/*.png`; `npm run android:assets` fans the same source out to the launcher. The web
manifest, the Android adaptive-icon plate and `ic_launcher_background` are all `#000000` now.
